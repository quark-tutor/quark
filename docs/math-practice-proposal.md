For Brandon and June. Written 8 November 2026 by Claude Code from the brief `docs/math-practice-brief-slice.md`, an
exploration: nothing is built, nothing on test or live is changed, and no API money was spent. Each choice has its
options and one marked **Proposed**; the decisions are gathered at the end as D1 to D12.

**Decided (8 Nov 2026).** Brandon, with June's answers: "go, out of order. All Proposed, with one change from June's
answers: slice 2 drops the word problems, or puts them last; the focus is the math, not reading a question." So word
problems are out of slice 2 and come last, after slice 3, only if the parents ask for them; "Read it to me" on

## In short

- **What is missing.** The puzzle slot gives one math *idea* a day, and a card is guess, clue, clue, handoff. Each
  of the 18 puzzle short lessons of weeks 1 to 3 is an idea with one question a layer (why 7 comes up most with two
  dice, a majority, the bar chart of 1786, eighths in a Hawaiian quilt, an array of stars on the flag, base sixty);
  arithmetic appears in them only in passing (6 × 8 = 48 in the flag's array, 2 cups in a pint). Arithmetic is
  learned by doing many of one kind with the answer checked at once, in an order that builds, and by meeting
  yesterday's misses again. Quark has none of that. The chat's reading holds against the records.
- **Proposed:** a sixth tile on the wall, **Practice**: eight problems a day, one at a time, in big digits with a
  number pad. The order of steps is borrowed from the first edition of Illustrative Mathematics' grade 2 and grade 3
  courses (CC BY 4.0; the current edition is non-commercial and is not used); the numbers are made by code; every
  answer is judged by code at once. No model, no Saturday work, no change to the Sunday build, $0 a day.
- **A wrong answer:** "Try again", then a nudge about the method, then the problem goes to a person and comes back
  tomorrow, and the next problem is an easier one. The screen never shows the answer.
- **The level:** up a step after a set answered all right the first time; back a step when two problems in one set
  go to a person; a parent can move it either way.
- **The first slice** is whole numbers only (sums and differences for the younger, multiplication into division for
  the older), small enough to be on the boys' iPads within two weeks.
- **The math, not the reading** (June, 8 Nov 2026): practice is problems in numbers; word problems come last, if at
  all.

**What there is to borrow.** No open source has a ready, ordered bank of facts that could be carried as data. So:

- **the order of steps** from IM's first edition, unit by unit, with the Progressions' stages of strategy inside each;
- **the problem types** from IM's practice problems and warm-ups, where one answer can be judged (a bare fact, a

| | What the boys get | What it costs the parents | What it costs the code |

| (c) A page off the wall the parents open with the boys | Practice when a parent sits down with them | Five to ten minutes a day per boy, which breaks the success line of under 30 minutes a week of parent time | (a)'s page, plus a way for a parent to open it on a locked iPad |
| (d) A practice set at the end of each puzzle card | A few problems on the day's idea (arrays, then a few facts) | Nothing more | The problems follow the puzzle ideas, which are not an order that builds (base sixty, then sea level, then a vote); and if the model writes them, they need the gate and cost money |

**Proposed: (a).** It is the one with the fewest moving parts that June would call recognizable: it touches no card,
no prompt, no gate and no Sunday build, it runs every day (fluency comes from daily, short practice), and it needs
no parent at the iPad. Six tiles sit better on the iPad than five (three and three across, two by three down).

For (a):

- **How many problems.** (a) **Proposed:** eight a set, one set a day; yesterday's misses take the first places,
  up to three, and the rest come from the child's step. When the set is done, the tile is done for today: there is no
  "one more set", because practice without an end is the infinite scroll of rule 4. (b) Ten, about six or seven
  minutes. (c) As many as the child wants. June's minutes (Q3) settle the number.
- **A wrong answer, under rule 3.** (a) **Proposed:** first wrong answer, "Try again."; second, the step's nudge, a
  sentence about the method written once for each step and never holding a number from the problem ("Make a ten
  first: how many more does the bigger number need to make ten?"), in the Common Core methods the school uses (make
  a ten, a number line, an array; decided 8 Nov 2026, from the Progressions); third, "This one is for a person." The problem
  goes to the parents' list with the three answers the child gave, comes back at the start of tomorrow's set, and the
  next problem in today's set is one from the step before. The screen never shows the answer. (b) The chat's order:
  a nudge, then an easier problem, then the same problem once more, then a person: up to five tries at one problem,
  long for a 7-year-old. (c) After the third try the answer is shown, as a worksheet's answer key would: this bends
  rule 3 and needs the parents' ruling (D4).
- **Yesterday's misses.** (a) **Proposed:** every problem not right on its first try comes back at the start of the
  next set, once, the same numbers; a missed day changes nothing, and nothing is said about it. (b) Phase 6's spaced
  return (a day, three days, a week), which `review_schedule` was made for: its rows point at `questions`, which
  point at cards, so practice would need its own; slice 3.
- **How the level moves.** (a) **Proposed:** the docs/12 dial, counted by the set rather than the question: a set
  whose new problems were all right the first time moves the next set up a step; two problems in one set that went to
  a person move it back a step; anything between stays. A parent can move a child's step either way on `/parent`
  (any guardian, rule 2). (b) A rolling score over the last 20 problems (move up at 90 per cent first-try right):
  smoother, harder to explain in one line. (c) Only the parents move it.
- **Rushing.** Answers typed faster than anyone could think are docs/12's "the session ends when the thinking
  stops", proposed and not built for the cards either. **Proposed:** not in the first slice; the seconds are kept,
  so the parents can see it on `/parent`, and the rule comes for cards and practice together.
- **Spoken and heard.** (a) **Proposed:** not in the first slice. The problems are digits, which both boys read,
  and the number pad is quicker and surer than Talk, which can hear "fifteen" as "fifty". "Read it to me" comes with
  word problems, where there are words to read: last, if at all (decided 8 Nov 2026; offered as slice 2). (b) "Read
  it to me" from the start: each new problem is a new line, so the first tap waits four to five seconds unless the
  night's firing also makes the day's problems.

## 4. Judging in code

Every answer is judged by code, with no model call, so **the API spend is $0 a day** (and $0 for the voice while
practice has none).

- **Whole numbers** (slice 1): the digits typed, with spaces and commas taken out ("1,000", "1 000" and "1000" are
  one number). The number pad offers nothing else, so there is nothing to misread.
- **Fractions** (slice 2): "3/4", and "3 fourths" or "three quarters" when Talk is on; right when the value is equal,
  unless the step asks for a named form ("as eighths"), in which case it must be that form.
- **Time** (slice 2): "3:45", "345", "quarter to four"; elapsed time as minutes ("45" or "45 minutes"). A clock face
  is drawn by code, so no picture needs a licence.
- **Money** (slice 2): "$1.35", "1.35", "135 cents"; right when the amount is equal.
- **Units** (slice 2): the question names the unit ("How many inches?"), so the answer is a number; a different unit
  typed with it ("48 feet") is not right.
- **What it cannot judge:** a shape drawn, a number line marked, the working shown, a "why", an estimate (unless the
  step gives a range), a question with more than one right answer it cannot list. Those are a person's: they stay in
  the cards' puzzle slot, the handoff, and the Ask box later.

## 5. The rules

- **Rule 3 (hints, never answers).** Holds as proposed in section 3: a try, a second try, a nudge about the method,
  then a person; the screen never shows the answer, and a nudge is written once per step so it cannot hold the
  problem's answer (a test holds that no nudge names a number its step can have as an answer). **The strain,
  named:** a fact like 7 × 8 is not discovered; a child who cannot reach it after a nudge learns it from a person or
  from seeing it. Keeping the rule sends those to a person and back tomorrow; bending it shows the answer after the
  third try. That is the parents' ruling (D4); **Proposed:** keep the rule.
- **Rule 4 (no engagement hooks).** No streak, no points, no stars, no badges, no timer, no "you missed a day", no
  second set. What makes a child do it: it is on the wall every day beside the cards, it is short and its end is in
  sight ("3 of 8"), and the house rule of docs/06 ("the Wonder Wall comes before other screens"). The step's name is
  shown to the parents, not to the child, so moving up is not a level to chase. If the boys skip it, that shows on
  `/parent`, and a parent decides what to do; the reward engine (docs/15) stays out.
- **Rule 5 (nothing reaches a child unchecked) and the policy gate.** **Proposed:** practice problems do not go
  through the gate. The gate reads what a model wrote, against the family's rulebook and the safety floor; a practice
  problem is a template written once by Code with numbers put in by code (`38 + 5`), and holds no subject the
  rulebook could hold back. The check is the parents' read of the sequence file, every step's title and nudge, before
  it ships, as with the wall's own sentences in `core/wall/words.ts`. Word problems, if they come (last, after slice
  3), are templates too, read the same way; if a model ever writes problems, they go through the gate. This reads rule 5's "every card" as not
  covering a generated sum, so it is named here for the parents (D9).
- **Rule 7 (minimal data).** One row per answer, as the cards have: the step, the problem as shown (`38 + 5`), the
  answer typed (at most 20 characters), right or not, which try, whether the nudge was shown, whether it went to a
  person, the seconds. One new thing is kept about each child: the step reached, a level like the reading level;
  nothing identifying, and nothing leaves Quark's database (no model, no voice in slice 1). *Touches rule 7* (D10).
- **Rule 8 (effort words).** The words: "Try again.", the nudges, "This one is for a person.", "Here's one to
  warm up." (before an easier problem), "That's today's practice." No "easy", no "smart", no "great job", no "wrong".
  They live in `core/wall/words.ts` with the rest, under its test. "Try again." differs from the cards, which never
  say "Not yet": that rule was made for a judge that misread right answers in a child's own words (21 Oct 2026), and a
  sum is judged exactly, so "Try again." is true.
- **Rule 2 (every guardian an equal say).** Either guardian moves a step; the last move stands; both see it.
- **Rules 1 and 6.** Arithmetic carries no belief, and the sequence is by the child's grade, never the child's sex.

## 6. Where it fits what exists

- **Tables.** (a) **Proposed:** a new table, `practice_answers`, one row per answer (section 5, rule 7), with the
  child's `session_id` from the wall's own `sessions`; and one column on `children` for the step a parent set. The
  current step is worked out from the last set and that column, as the wall works out where a card is from the
  attempts alone. (b) Reuse `attempts`: each row needs a `questions` row, which needs a card, an idea and a theme, so
  every generated problem would make four rows the Sunday build normally makes. One migration either way.
- **The sequence.** A file under `plan/`, `plan/practice.yaml`, like the library: the steps in order, each with a
  key never reused, a title for the parents, its grade, where it was borrowed from (with the licence and credit
  line), the kind of problem and its number ranges, and its nudge. Checked by a validator, as `validateLibrary()`
  checks the library. Written once; added to when a boy nears its end.
- **The problems.** Made on the server when the child opens the tile, from the step, the child and the day, so a
  reload shows the same set and nothing is stored before it is answered.
- **The Sunday build and the Saturday pick:** untouched. Practice runs from its own file and needs no Saturday work,
  which is the point. The night's firing (lines made ahead) is untouched too.
- **The wall.** `loadWall()` adds the sixth tile; a new page, `/kid/practice`, and a new route,
  `/api/kid/practice`, both through `lib/wall.ts`'s device scope, with `lib/kid-wiring.test.ts` holding them to the
  same rules (no link out, nothing played by itself, nothing logged but a fault's message).
- **The parents.** A *Practice* block on `/parent`: each boy's step and the control to move it, the last seven days'
  sets, and the problems that went to a person, with the answers given.

## 8. What this does not solve

Practice drills a method a child already has. When a boy does not have one (why 38 + 5 crosses a ten, what a
fraction of a shape is), a person shows him, or, later, the tutor does: that is the Ask box and hints as a
conversation (the *The tutor* project), not practice. Practice also does not judge working, drawings or reasoning,
and does not replace the puzzle slot's ideas, which stay as they are. The two inbox rows of 28 Oct (different kinds
of learning so the format does not go stale; a more Socratic card) are not answered here, though Practice is one new
kind.
